Don't deploy what the pipeline didn't build.

Every CI build writes its image digest to Solana. Before deploy, oath verify or a Kubernetes webhook blocks any image with no record.

How it works

      
    
        
  1. 
          
          
    Build
    
          
    CI builds the image.

  2. 
          
          
    Record
    
          
    Its digest goes to Solana, signed by the CI key.
    
          
        
    3. 
        
  3. 
          
          
    Verify
    
          
    Before deploy, oath verify or the webhook looks for a record.
    
        
    4. 
      


      

        Details
        

          
exit 0 verified, the deploy proceeds

          
exit 1 no record, the deploy stops

          
One Memo per build:

          
pod1|ghcr.io/me/app|3f9a1c0d2b7e|sha256:<64 hex>|2026-10-12T21:04:11Z

          
version | image name | commit (12 chars) | image digest | time

        

      

    

  


  

    

      
Set up

      
Run oath init once to create the CI key. Then:

      

        

          
          
          
        


        

          
Add SOLANA_SECRET_KEY as a secret and OATH_SIGNER (the public key) as a variable.

          


# after the build: record the digest
- uses: Tymofii-thc/oath@main
  with:
    image: ghcr.io/${{ github.repository }}
    digest: ${{ steps.build.outputs.digest }}
    secret-key: ${{ secrets.SOLANA_SECRET_KEY }}

# before the deploy: fail the job if there is no record
- uses: Tymofii-thc/oath/verify@main
  with:
    signer: ${{ vars.OATH_SIGNER }}
    image: ghcr.io/${{ github.repository }}:latest

        


        

          
Checks every new Pod and fails closed. Start with mode=audit, then switch to enforce.

          


helm install oath oci://ghcr.io/tymofii-thc/charts/oath \
  --version 0.2.0 -n oath-system --create-namespace \
  --set signer=<pubkey> --set mode=audit

        


        

          
Exit codes: 0 verified, 1 not verified, 2 error.

          


# once: create and fund the CI key
npx --yes --allow-git=all github:Tymofii-thc/oath init

# check an image
npx --yes --allow-git=all github:Tymofii-thc/oath verify --signer <pubkey> --image ghcr.io/me/app:latest

Threat model

      

        

          
            

              Attack
              Result
              How
            

          
          
            
Image swapped under the same tagBlockedThe new digest has no record.

            
Push or kubectl apply that bypasses CIBlockedoath verify exits 1; the webhook denies the Pod.

            
Registry token leakedBlockedThe attacker can push an image but cannot record its digest.

            
Record made for a different image nameBlockedRecords are bound to the image name.

            
Old, valid digest replayedLimitedLimit it with --max-age or oath revoke.

            
CI key compromised, then revokedMitigatedRemove it from the signer list: its records stop counting at once.

            
Registry, RPC or webhook downFail closedNew Pods are refused, running Pods are untouched. The CLI exits 2.

            
Forged record that only mentions the signerBlockedOnly transactions the signer actually signed count.

            
Running Pod's image edited, or debug container addedBlockedThe webhook checks updates and ephemeral containers too.

          
        

      


      

        
Not covered

        
    
          
  • Stolen CI signing key. Whoever holds it can record a forged digest. --quorum 2 adds a second approver key but is off by default. Rotation, revocation and --max-age limit the damage. The approve page is tested with Phantom only.
    • 
          
  • Malicious code built honestly. The chain proves the signer recorded a digest, not that the code is safe. --attest checks which workflow built the image, not what is in it.
    • 
          
  • Mainnet in CI. Supported, but CI has not run on live mainnet. devnet is the default and has no retention guarantee.
    • 
          
  • Availability and existing Pods. An RPC or registry outage blocks new Pods (images verified in the last hour still pass). Pods created before install need oath audit.
    •
